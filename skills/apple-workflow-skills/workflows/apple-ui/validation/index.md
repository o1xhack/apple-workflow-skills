# 实际 UI 验证

按问题选择最短有效路径；不要每次全量运行所有环境。

| 问题 | 路径 |
| --- | --- |
| 组件外观、排版与状态布局 | 生产组件的原生 Preview |
| 导航、键盘、弹窗、权限、导入、生命周期 | 完整 App 的模拟器或目标环境 |
| 传感器、后台、热量、能耗、真实系统服务 | 真机与相应观察时长 |

## Preview

使用实际生产 View，注入有界、可重复的加载/空/错误/长内容状态。预览初始化不能发真实同步、全库扫描或后台录制。
现场发现 Xcode 原生预览工具；不可用时使用 Canvas 或现有模拟器，明确实际路径，不为镜像工具强迫工程重构。
拿到本轮实际渲染图片并查看后，才算视觉检查；编译成功、返回路径或浏览器加载不等于看过画面。
检查截断、空白、隐藏模块收拢、字号、安全区域与操作可见性。修改后重新检查相关状态，不拿旧图充当新结果。

## 完整 App 与真机

Preview 环境不保证真实导航、键盘与加载生命周期一致。实际操作受影响的步骤后才报告交互通过。
示例数据验证布局，授权真实数据验证实际业务；私有快照不进入 Git。
模拟器的安装成功或出现 Home Screen 不代表测试通过。记录 App 内观察。
真机检查按症状选择静止/移动/前后台/长时场景，不将几分钟结果推断成全天续航。
项目工具或专项 skill 可用时按其当前文档使用；不假定工具名字、版本或连接存在。

报告使用路径、实际看见与操作的结果、残余缺口。普通 UI 小改动无需独立长报告。
