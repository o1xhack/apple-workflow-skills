# 隔离与诊断

- actor 在可能挂起的 await 前后允许其它工作改变状态；返回后重新核对请求、缓存版本和资格，不继续沿用过期假设。
- 无挂起的连续 actor 代码不会被另一次 actor 调用插入。保存 await 结果到局部变量可简化逻辑，但不自动避免并发重复下载。
- 去重可保存 in-flight 任务，但必须定义谁拥有任务、单个等待者取消是否取消共享任务、失效后旧结果是否允许写回。
- UI 所有状态通常属于 MainActor；普通共享数据也可用独立 actor、不可变 Sendable 值或正确同步机制。选择真实语义，不随意扩大隔离范围。
- Sendable 表达跨边界安全。编译器已能证明转移时不要多加标注；sending 等新能力须核对版本和所有权语义。
- 协议隔离不匹配时明确协议使用方是否需要 actor 数据；不要用 nonisolated 把仍访问隔离状态的方法伪装安全。
- 非隔离 async 的执行行为取决于工具链与特性设置；不能把某个 Swift 版本行为当所有 target 默认。
- @unchecked Sendable、nonisolated(unsafe)、@preconcurrency 只能在有明确兼容/同步依据时采用，并记录为什么编译器无法证明。
- 不用 semaphore 或同步 wait 阻塞协作线程来等待 async 结果。

测试缓存共享请求、失效与重新加载交错、取消等待者和过期结果回写；单个成功请求不能证明 actor 正确。
